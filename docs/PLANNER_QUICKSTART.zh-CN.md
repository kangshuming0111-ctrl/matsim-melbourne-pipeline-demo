# 用 IF Line 讨论一个道路方案

本软件当前适合做**局部交通概念方案的对照试算**：在同一批合成出行需求下，比较道路调整前后哪些出行、哪些路段发生变化。它不是 Google Maps 导航，也不是已校准的城市发展预测器；3D 城市用于画方案、找位置和检查空间问题。

## 先体验已经完成的实验，不必等新仿真

1. 双击项目的 `start.command`，在浏览器打开 <http://127.0.0.1:8000/>。
   不要直接双击 `index.html`。
2. 找到“成组规划实验”中**全部完成**的墨尔本 CBD 案例。
   正式记录编号为 `cbd_expanded1037_detour_10it_review_r02`。
3. 先打开种子 4711 的“封路”，比较封路与原基线；再点“替代道路 vs 封路”，
   比较增加这条道路是否缓解了同一次封路的影响。
4. 这些按钮打开的是**已有结果回放**，不会开始新的 MATSim 计算。
   三个种子各有一套完整结果，不要把不同种子的两个场景混在一起对比。

三个方案使用同一份 1,037 人合成计划，每次运行 10 次迭代。三个种子的汽车
平均耗时差显示：封路相对基线约 +7.530 秒，增加替代道路后相对基线约
+7.628 秒；替代道路相对仅封路约 +0.098 秒。正值表示更慢。
**这条候选道路没有在该指标上显示收益**；很小的变化不意味着统计显著或现实伤害。
这是软件应当允许得出的结果，而不是必须把新增道路涂成绿色。

## 工作台里优先看什么

1. **先确认比较对象。** “参照方案 A”是问题的参照，“比较方案 B”是候选方案。
   人口、种子或仿真设置不能匹配时，系统拒绝比较。
2. **再选时段与交通方式。** 例如早高峰 7–9 时、汽车；点击“应用条件并分析”。
   条件改动但未应用时，导出被锁定，不能把旧数值当成新条件的答案。
3. **先看整趟出行，再看道路。** 平均变化可能很小，但部分出行仍可能明显变慢。
   “变快／变慢／变化小于 1 秒”和 P95 能帮助发现这件事；1 秒是显示容差，
   不是显著性标准。
4. **点击路段看实际观测。** 可将多条有向路段选为走廊，重新分析经过它们的出行。
   同一条街的两个方向是不同 link，可以分别选入。没有经过该走廊的出行不混进
   走廊队列；该筛选也不等于附近居民或某个社区的福利分析。
5. **检查不可用数据。** 灰色不等于“没有影响”；新路、被拆分的路段或一侧没有
   通行观测，不能直接算成节省多少秒。封路可能使车辆绕行，即使剩余路段本身
   几乎没变慢，整趟出行也会更久。
6. **需要定位时回到 3D。** 路段详情可定位到下方对应 B 场景。3D 原始全天图层与
   工作台分时段图层有明确区别；不要混读两套条件。
7. 下载 HTML 讨论报告或 JSON 核对数据。报告保留应用条件、缺失记录及来源依据。
   原始代理行、完整事件文件和受限原始数据不应不经审查就公开上传。

## 做自己的方案

- 从完成且有记录的基线进入 3D 编辑器。修改已有道路限速／容量／机动车通行，
  或自由绘制新道路并接入已有网络。
- 先检查连接和建筑轮廓冲突，再运行。建筑编号可定位；冲突确认仅表示愿意做
  概念试算，不是拆迁批准，也不会把建筑从场景中删除。
- “高架”当前通过道路相对高度、长度与连接拓扑影响方案，不包含结构承重、
  完整纵坡／净空、转弯半径、匝道容量或施工设计认证。
- 真正运行可能需要等待。运行失败时查看本次错误和记录，不拿上一次成功结果
  替换。完成后确认本次运行编号，再进入同一个影响工作台。

## 现在不能回答的问题

不能据此承诺现实通勤会减少多少分钟、哪块地会升值、城市将新增多少人口，
也不能判断桥梁能否施工或哪个方案社会总收益最高。当前没有观测交通校准、
诱发需求／土地利用反馈、成本／排放／公平性评估；公交为传送模式而非真实班次
车辆仿真。其他区域、冷机器安装及所有用户画法也没有与 CBD 相同的验证证据。

更详细的指标定义见 [工作台说明](IMPACT_WORKBENCH.md)，运行和结果依据见
[九次对照实验](PLANNING_CASE.md)及[验证记录](VERIFIED_RUN.md)。
