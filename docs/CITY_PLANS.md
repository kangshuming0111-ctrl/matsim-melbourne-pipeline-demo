# City-plan prototype / 组合交通概念方案

## 操作

1. 按主 README 准备数据，打开 `http://127.0.0.1:8000/`，选择带审计记录的 CBD 基线，进入 3D 沙盘。
2. 用“俯视画路”定位，移动鼠标查看有实际设计宽度的道路预览，点击逐点画线；端点接入已有机动车节点。直接拖动地图蓝色控制点改走向，空白处拖动仍是旋转。吸附受屏幕 22px 及设置的米数上限共同限制；按住 Shift 或关闭吸附可放置自由点，选择随控制点保存，后端不会偷偷重新吸附。自由端点必须最终接到节点，否则检查会明确失败。两端连接到路段内部、曲线手柄暂未实现。
3. “生成高架与两端过渡段”根据路线长度插入过渡控制点，保留已有转折。默认按相对抬高坡率 8% 建议过渡长度，过短路线不会被强行拉伸。蓝色纵断面控制点可上下拖动，也可聚焦后用方向键；端点锁定 0。图上同时显示地面与道路，但地形含视觉夸张，**不能量取工程高程或净空**。这是相对地形抬高方案，尚非独立的桥面纵向线形；没有桥墩、结构或合规结论。“侧看高度”和“近看路线”提供针对草案的视角，不改变地块。
4. 单条路线无需先点“加入方案”：画好后即可检查。若要组合多项修改，可先点“将当前修改加入方案”，再画另一条路，或点击已有机动车 link 调整限速、容量或封路并加入清单。容量百分比始终相对基线，重复修改同一参数以清单中最后一项为准。
5. 清单逐项编辑、移除；撤销/重做方案修改最多 50 步。画路有独立的“撤销编辑/重做编辑”，一次拖动只占一步；支持 Ctrl/Cmd+Z、Shift+Ctrl/Cmd+Z。右键单击撤回一点（右键拖动仍平移），Esc 暂停画路；取消拖动或窗口失焦会恢复拖前位置。“保存草案”仅保存到当前浏览器和当前基线，不是云端账号同步。
6. 点击“检查当前路线与方案的冲突”，自动加入当前画路草案；编辑旧项目则替换该项，不重复添加。显示独立的冲突总数和可滚动建筑列表，移动点等操作提示不覆盖列表；点击稳定编号定位，原始名称（如有）保留。新草案会明确标记上次检查已不覆盖全部内容，检查失败不显示为零冲突。
7. 比较入口在尚未检查时显示“检查方案以继续比较”，首次点击只检查、不启动仿真。若有冲突，查看并勾选风险确认后才启用运行按钮；按钮旁始终说明缺少的条件。这不代表拆迁或施工许可；建筑不会消失。重新检查或修改方案会重置风险确认。
8. 运行 MATSim。任务复用基线人口、种子和轮数，输出独立网络、日志、事件、比较和审计记录。运行前的画面仍明确是基线。完成后为当前分支结果，点击“返回基线继续编辑”可继续设计。窄窗口可用“参数面板”切换，避免面板遮住整个地图。

## 接口 / 实现边界

- `POST /ifline/plan/check`: `{baseline_run, plan:{operations, building_labels}}`。无仿真副作用；返回规范化方案、有效道路段、变更清单、建筑冲突、说明及 token。
- `POST /ifline/plan/run`: 上述字段加 `name`, `check_token`, `acknowledge_conflicts`。API 与后台工作者均复核；返回不可混用的 `job_id` 和 `run_id`。修改后凭据无效；未确认的冲突不入队。
- `wrapper/planning.py`: 独立内存编译与平面冲突审计。所有操作成功后才写新路网；保留原文件。地面路段与地面机动车 link 相交则分段接网；高架中段不接地面。**与人行/骑行专用 link 的交叉不自动连接**。
- `wrapper/static/plan-state.js`: 纯数据历史；`planning-ui.js`: DOM、保存、检查、提交适配。
- `cityPlanFlow()` 是按钮与提交入口共同使用的动作判定：返回 `blocked`、`check` 或 `run`；仅 `run` 包含由当前已检查方案、token、名称和风险确认组成的请求快照。不存在另一套 `cityPlanReady()` 判断或旧的新道路直跑入口。`index.html` 的 `refreshStudioRunButton()` 仅处理延迟脚本尚未就绪时的委托，不拥有运行规则。二维单项备用编辑器及其 API 仍保留。
- `road-design.js`: 无 DOM 的路线里程、相对高度过渡建议、剖面采样和草案历史；`road-editor.js`: 鼠标实时预览、拖动所有权、侧面图编辑与建设视角。临时预览不进入方案、结果或保存数据。高度编辑不改变 XY。
- 新道路操作可含 `snap_points:[true,false,...]`，长度必须与控制点一致，旧草案默认全部 true。false 保留原坐标；false 端点需在地面机动车节点的 1e-5m 内。该字段纳入检查凭据，检查后改变会失效。
- `road-mesh.js`: 用既有地形采样器生成新路网表面；新增道路采用物理宽度换算，旧道路/车辆仍有可视化夸张，不用于量取净空。渲染不更改地块、建筑或既有深度缓冲设置。
- 高度通过 link 的 `ifline:height_from/to` 自定义属性保存到 MATSim 输出，回放 keyframe 第五字段为相对地面米数。MATSim 中的区别来自连接拓扑、长度和输入参数，不是一个新的桥梁动力学模型。

## 限制与结果解释

新道路检查使用完整的已知建筑源，而不是 3D 显示上限裁剪后的建筑列表。
检查以编译／吸附后的道路宽度走廊为准：走廊越过建筑缓存覆盖范围、源缺失或
存在无效／不完整轮廓时，检查失败，不能显示“0 个冲突”。源数据哈希绑定检查
凭据；修改源后必须重新检查。没有新增道路占地的限速／容量／封路方案标记为
无需本项筛查，不假装扫描了建筑。显示的源要素数不等于唯一建筑栋数。
已保存草案仍可读取，但之前的检查凭据必须重新生成；历史仿真不会被改写。

- 仅限已准备的区域；1–12 项修改，每路 2–32 点、两端地面连接。高度 0–50 m、相对高度变化/平面距离 ≤12% 是原型输入保护，**不是工程合规值**，且尚未累加真实地形纵坡。
- 建筑按平面轮廓加道路宽度保守检查，不判定立体净空；可能报告高处跨越的建筑，也无法覆盖缺失的 OSM 建筑。不是完整碰撞引擎或地籍审查。
- 当前基线 XML 未保留完整的桥梁/隧道层级。未标记高度的 link 暂按地面处理；新增地面交叉口需人工核验，不能声称已经还原真实城市的立体交通连接。
- 允许确认冲突后做概念试算；路线与建筑的现实冲突不会因运行成功而解除。图形深度遮挡正确不等于道路可施工。
- 没有桥墩/支座/隧道、信号配时联动、桥梁结构、土地价格、拆迁成本、诱发需求或长期人口反馈；没有增加第二个预测引擎。
- 对于拆分/新增 link，不直接用旧整段延误作对照；无双侧观测也不当作改善。全网出行时间和方式份额仍显示，但单种子三轮只是原型验证，不是统计稳健性或校准证明。
- 保存的草案需在同一浏览器读取；方案一旦运行，服务器将完整方案和检查报告写入 `output/ifline/<id>/scenario.json` 与 `comparison.json`。不要公开分发完整数据前先跳过原始数据许可检查。

## 回归

```sh
.venv/bin/python -m unittest discover -s tests -v
node tests/plan_state.cjs
node tests/road_design.cjs
.venv/bin/python -m http.server 8765 --bind 127.0.0.1 --directory tests/browser
```

应用在 8000 端口运行时，依次打开 8765 下的 `skyline_depth.html`、`landuse_geometry.html`、`building_geometry.html`、`road_geometry.html`、`road_editor.html`、`plan_workflow.html`。前两个专门防止旋转时的深度撕裂与地块孔洞丢失；建筑、道路页面检查屋顶轮廓和贴地表面；编辑器页面用真实 Three.js 和合成指针事件检查预览、捕获、撤销、取消、锁定与地形不变。方案流程页面使用真实前端适配器、模拟 API 检查自动纳入草案、冲突确认、过期响应与提交失败，不运行 MATSim。合成事件并不能替代真实浏览器的鼠标捕获，需另在 CBD 页面手动拖动验证。测试通过不构成对任意输入和任意硬件“绝不穿模”的保证。
