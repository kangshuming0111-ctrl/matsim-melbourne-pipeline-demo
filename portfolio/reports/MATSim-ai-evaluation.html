P2 AI 分析助手：评估与面试说明

2026-10-19 · release 2026.10-p2 · 本地真实推理：Qwen3 4B Instruct 2507 Q4_K_M / Ollama 0.40.6。

结论

冻结实现后的预留集 20/20 通过；其中可核对数值题 14/14 正确，证据不足题 5/5 正确拒答；数值引用检查失败 0，降级回答 0。开发集最终为 30/30。这是有程序约束的完整系统成绩，不能称为裸模型正确率，也不是生产可靠性证明。

无 AI 的确定性基线在同一预留集为 20/20，数值题 14/14。因此本次没有证明 AI 提高了数值准确性；其作用是自然语言路由和受限解释组织。这套题与基线规则均由同一开发过程编写，对确定性基线也比较友好。

AI 行的延迟只统计真正调用模型的请求；确定性行统计全部请求。原始 summary.json 同时保留含快速拒答的全请求延迟。失败样例、输入、预期、完整回答、模型调用元数据和判定均保存在同名 answers.jsonl，未覆盖旧版本。

第一版开发结果只有 13/30：JSON 合法，但模型遗漏 seed、改了单位、混淆比较方向。第二版要求所有结构化字段，仍只有 14/30。最终版本将用户明示的 seed、方式、单位、比较方向等作为强制参数。开发集 8 道、预留集 8 道使用了这类纠正。raw_model_plan 与 explicit_parameter_constraints 可逐题审计；这是确定性纠正后的成绩。

早期确定性基线 28/30 还暴露了假设数组里的数字类型被当作非法时间。修复让数字先经过同一时间解析入口，保留真实零、空值与非法值的区别。这个发现与真实仿真文件含缺失值是两回事。

评估设计与边界

• 50 题在开发前锁定 SHA-256：30 道开发题、20 道未参与提示词调试的预留题。预留集由同一作者编写，并非独立第三方盲测。

• 数值预期由 native CSV 的独立算术及预先声明的计数/边界规则构造，不调用助手生成答案；容差为相对 1e-10、绝对 1e-8。检查指标、单位、状态、工具及引用。

• 第一次预留运行前冻结助手、模型适配器、测量解析器、评估器、SQL、聚合证据哈希与模型摘要。记录只读的预留开启标记；不把再次运行称为新的未见测试。

• 范围：运行查询、均值/差值、单 seed 配对统计、时间/距离单位、缺失/零/全缺失、错误运行、证据不足、写操作与启动仿真指令。拒答可能由模型前的确定性规则完成。

• 数值事实必须有单位、来源与 run ID；假设数组明确标为 hypothetical_fixture，不伪装成仿真数据。来源检查确认结构及已核验 SQL/文件哈希，并非人工逐条外部审查。

• 15 道预留题真正调用了本地模型，5 道在模型之前拒答。模型只返回结构化计划和既有事实块的排序，不编写任意因果结论。

• 这不是 RAG 文档检索、训练自有模型或通用代理。三种子/九次仿真不能证明真实交通效果、统计显著或唯一因果机制。未做独立用户评审、陌生人措辞集或负载测试。

延迟与成本

预留集中模型请求 p50 7.184 秒、p95 10.195 秒；含快速拒答的全请求 p50/p95 为 7.114/8.813 秒。小样本顺序测试，模型此前已加载；首次启动/模型加载不包含在这些分位数中。

单次外部 API 费用 US$0，因为实际使用本地推理。电费、机器、存储、下载与安装时间没有折算，不能说总成本为零。开发机 i5-14600KF、Windows 约 32 GB 内存 / WSL 约 15 GB；本次使用 Ollama CPU 推理。浏览器和 API 并发有限：助手一次仅处理一个请求。

能拿去面试讲的主线

“I connected a local LLM to read-only analysis tools. SQL and Python compute the numbers; the model selects a typed query and organizes evidence-backed explanations. Early evaluation exposed semantic errors even when JSON was valid, so I bound explicit parameters deterministically and kept the raw plans. On a frozen 20-question internal holdout, the guarded system passed 20/20. The no-AI baseline also passed 20/20, so I claim traceable interaction and tested boundaries, not improved numeric accuracy.”

个人贡献请按实际参与说明，包含 AI 辅助编码；模型、MATSim 引擎和上游 R 工具均不是本人训练或原创。补充讲解见 AI_INTERVIEW.md。下一步有价值的验证是由独立读者编写同义问法、未见问题与错误假设，另建测试集，再衡量模型相对规则的增益。
